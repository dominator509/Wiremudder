# Branding Policy

WireMudder branding is introduced through application metadata, icons with original provenance, package identifiers, release names, documentation, and narrowly verified UI strings. It does not justify mass class renames, source moves, namespace churn, or removal of Mudlet attribution.

Brand assets require original or licensed provenance. A branding change that increases upstream merge conflict must justify the cost in an ADR and include a rollback.
